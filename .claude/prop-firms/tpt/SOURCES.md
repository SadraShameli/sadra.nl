# Take Profit Trader: Source Ledger

One row per primary-source document used anywhere in this firm's tree. Update this file every time a source is added, re-fetched, or re-verified.

Take Profit Trader's help center is a standard Zendesk Help Center (`takeprofittraderhelp.zendesk.com`). Its HTML pages (and `robots.txt`/`sitemap.xml`) were Cloudflare-blocked (HTTP 403/404) for direct curl and WebFetch, same as every other firm's help center fetched this session. Unlike those firms, Zendesk exposes a public, unauthenticated Help Center REST API (`/api/v2/help_center/en-us/articles.json`) that was not behind the same block : the full article catalogue (title, section, dates, and full HTML body) was fetched directly through that API in one paginated call (87 articles, one page), with no browser relay needed. Article bodies were converted from HTML to plain text with a small local script (strip script/style tags, convert list items and block-level closes to newlines, decode HTML entities) rather than pasted or hand-copied.

**Completeness:** all 87 articles returned by the Help Center API were read in full this pass (verified by diffing this session's own Read tool calls against the full article-file listing : initially 5 short, none unread; those 5 had been read directly from the API's own JSON preview before being split into individual files, and were then re-read individually to close that gap with certainty rather than rely on the inference). No sitemap/robots.txt fallback was needed given the API worked directly.

**Re-verification pass (2026-09-19):** all 49 of the 87 articles not cited in `test-pro.md`/`pro-plus-live.md` were independently re-read against their own full cached content to check the exclusion itself, not just its title. 44 of 45 held up as genuinely out of scope (subscription/billing UI, platform-connection how-tos, affiliate program, rewards/points system, promo FAQs already superseded by the two cited ones). One did not: "How to Check Your Renewal Date" documents a free, automatic reset-on-renewal mechanic for disabled Test accounts that `test-pro.md`'s own "Resetting after a loss" section never mentioned (it only covered the paid, on-demand Reset Fee path). ## Known unresolved source gaps and inferences (not fetch failures : do not re-attempt these URLs)

- **The "2026" year on the 3-day-eval cutoff** ("from August 17th onward") is inferred from the 50AND3 article's own creation/update timestamps, never stated as a literal year anywhere in the source text.
- **PRO's own per-size Max Contracts table** is carried over from Rule 2 (which is not explicitly scoped to Test in its own title); no separate PRO-specific contract table exists in any source read this pass.
- **The Bond-Auctions "30-Year Bond" symbol mapping to UB** (Ultra U.S. Treasury Bond Futures) is this tree's own inference : the Approved Instruments list contains no plain "ZB" symbol, and no source states the mapping explicitly.
- **PRO+'s own per-size drawdown dollar figures** ($25K/$75K/$100K/$150K-origin tiers) are unconfirmed : only the $50,000-origin tier's $2,000 EOD Drawdown is stated verbatim anywhere in the sources read this pass. The underlying mechanic (PRO+ drawdown = originating PRO account's own starting drawdown) is confirmed for every size; the dollar figures are not.
- **Engine cross-check, both previously-reported conflicts refuted on re-check (2026-09-19)**: `TptLive.ts` sets `requiresLockForWithdrawal: false` and `LivePlan.withdrawableAmount()` honours that flag, so the engine does not gate a PRO+ withdrawal behind the drawdown lock and does not contradict "Advantages of PRO+"'s "No buffer zone requirement for withdrawal" claim. `LivePlanInit` does have a `maxConsecutiveIdleDays` field, set to 7 in `TptLive.ts`, so the Weekly Trading Requirement is modeled; the open caveat is that 7 days is derived by analogy from PRO's own weekly rule and a calendar-week rule is not identical to a rolling 7-idle-day counter. Both are documented in `pro-plus-live.md`'s own Not Confirmed section and `README.md`'s Documentation Scope; neither was fixed, per the `prop-firm-docs` skill's own scope (documentation pass, not an engine-editing pass) unless the user explicitly asks.
