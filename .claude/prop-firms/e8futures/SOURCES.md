## Known unresolved source conflicts (not fetch failures: do not re-attempt these URLs)

- **E8 Signature Futures' existence as a currently-sold product: RESOLVED (2026-09-20).** Two articles (`10207237-available-trading-platforms-for-futures`, `14595962-how-can-i-change-my-trading-platform`) both state E8 Zero Futures is "currently the only available product for this market." Per this tree's source-authority rules, the dedicated Signature Futures rules article and the dedicated Signature payout-caps article (both plan-specific) outrank these two general platform articles on Signature's own existence; the platform articles' claim is now treated as stale or inaccurate boilerplate, not a live conflict. See `signature.md`'s Other Confirmed Rules section.
- **35% Best Day Rule worked-example typo.** `11865587-35-best-day-rule`'s own Scenario A table labels its 35%-of-total-profit computation as "(× 0.40)": internally inconsistent with the rule's own name and its own correctly-computed $665 figure ($1,900 × 0.35). Treated as a source typo; 35% is used throughout.
- **`minDaysAfterPassForPayout` engine/doc framing: RESOLVED on the documentation side (2026-09-20).** Current sources (`9448349-what-is-payout-on-demand`, `15272556-everything-about-payouts-when-how-how-fast`) both explicitly state the "3 days to first payout" figure is not a separate rule, only an emergent property of the 35% Best Day Rule's math; per this tree's recency rule, these current sources control over the older, Wayback-archived version of the Signature article that the engine's own code comment cites. This is a current-vs-stale-source question, not two live sources disagreeing, so it is no longer tracked as an open conflict here; `signature.md`'s Payout Frequency row states the current framing directly. The underlying engine/doc mismatch (the engine itself still hardcodes a 3-day gate) remains open and is tracked in `README.md`'s Engine/doc mismatches note, not here.
