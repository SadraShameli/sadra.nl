Partway through this pass, direct raw-curl access to `support.lucidtrading.com`'s individual article pages was retested and found to succeed (HTTP 200, real content, not a challenge page) — the block appears to have relaxed for that subdomain's article paths specifically. The main `lucidtrading.com` root domain remained blocked throughout; its homepage content in this tree comes from a Wayback Machine snapshot instead. Every `support.lucidtrading.com` article below was fetched directly via raw curl once access succeeded, not through WebFetch's LLM summarization pass — this matters because a WebFetch summarization of one of these same articles (LucidPro Payouts) was cross-checked against the raw version during this pass and found to have blended two separate tables' figures into one incorrect range, confirming the same summarization-corruption risk already documented elsewhere in this doc tree for other firms.

## Completeness verification (sitemap-based, not just search-driven)

`https://support.lucidtrading.com/sitemap.xml` was fetched directly on 2026-09-18 after the user directly questioned whether this pass's help-center research had been exhaustive. It lists 69 `<url>` entries: 10 collection pages and 59 articles. Every one of the 59 has now been read except "Our Mission" (fetched and read anyway; confirmed pure marketing copy with no rule or figure). This is a materially stronger completeness claim than "we searched for it and didn't find it": every gap listed below is now a confirmed absence from the full article index, not a possible search-methodology miss. Any future re-verification pass for this firm should re-fetch this sitemap and diff it against this table rather than relying on search alone.

**2026-09-19 re-audit — LucidBlack and LucidMaxx articles actually read, not just categorized.** The 11 articles originally listed below as "explicitly out-of-scope... not fetched" were themselves re-fetched and read in full this pass, prompted by the user asking, firm by firm, whether every sitemap article had genuinely been read (it had not, for these 11 specifically — they had been correctly identified by the sitemap sweep but their exclusion was never checked against actual content). Findings:

- **LucidBlack (7 articles, Evaluation Account / Funded Account / Payout Objectives / Consistency Percentage / Scaling Plan / Drawdown / Live)**: Legacy status held up. Each article's own page metadata and breadcrumb name the parent collection "LucidBlack (Legacy)," and all 7 share a within-47-second last-edit timestamp consistent with an administrative reclassification. Still not documented as its own plan file. One nuance worth recording: the visible body prose of all 7 reads in ordinary, present-tense, active-product promotional style with no explicit deprecation language anywhere — a reader seeing only the rendered page, not the metadata, would not detect deprecated status from the prose alone.
- **LucidMaxx (4 articles, Overview / Eval Rules / Cooldown / Eval Pricing)**: invite-only framing was accurate but incomplete, and is now corrected. The Overview article states plainly that LucidMaxx access is earned via risk-team invitation, not purchased directly ("LucidMaxx status is earned, not requested"), but the other three articles describe an ordinary, self-serve, dynamically-tiered-pricing evaluation cycle available once that status is earned — which is why they read as generally-documented content with no invite-only language of their own. Now documented in `lucidmaxx.md`.
