# Prop engine audit: fix plan and tracker

Every confirmed and disputed finding from the 2026-09-23 engine and CLI audit, plus the eight test gaps, is tracked here until it is fixed and verified. Nothing is dropped: an item leaves `todo` only for `done` (fixed, regression-tested, reviewed, re-verified) or `blocked` (with the reason).

- **Source record:** [`audit-items.md`](audit-items.md). It holds each item's original report plus both independent reviewers' confirmed restatement, which is the authoritative description.
- **Process:** ECC `orch-fix-defect` per item. Write a failing regression test first, fix it to green, then `code-reviewer` + `typescript-reviewer` review, then typecheck/lint/targeted tests. GATE 2 (commit) is skipped: the user does all commits.
- **Firm data:** per `.claude/CLAUDE.md`, every firm value is re-checked against the firm's live site before it changes. Blocked sites (Apex, Tradeify help, E8 help: HTTP 403 on 2026-09-23) need the user to paste the page.

The `--funded-reset` help lists each offering plan's terms from the plan data (`describeFundedResetTerms`), never a hard-coded copy. The funded DP does not model it: `optimize dp --funded-reset` opts the plan in through `withPlanOptIns` and prints the `FundedResetNotModeled` gap line, while its empirical validation sim does take the reset, so the two can differ by the reset's value and spend.
