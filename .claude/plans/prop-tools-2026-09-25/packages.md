# Work packages (prop tools)

Generated by the ECC planner on 2026-09-25 from `DECISIONS.md` and the research passes; revision 2 folded in the architecture, trader and React reviews; revision 3 folds in the second critique (see PLAN.md "Review findings resolution (revision 3)"). Package numbers are stable; revision 3 adds PT-47, PT-48 and PT-49.

Each package runs under ECC orch-add-feature:
1. `ecc:tdd-guide` writes failing tests first and confirms RED (the failures must be the missing behaviour, not unrelated errors).
2. It implements to GREEN.
3. The listed reviewers review, followed by a fix loop and a re-review.

Packages in the same wave own disjoint files. Concurrent waves of different lanes are checked for overlap by the orchestrator before they start. The orchestrator also applies PD-42: no package in a wave may change an enum, union or interface that another package in the same wave switches over, maps exhaustively, constructs or renders.

Standing rules for every package:
- No code comments. No em dashes in code, UI text or docs.
- PascalCase for domain files, camelCase for utilities, hooks and routes. `~/` imports; add to barrels.
- Enums, not repeated string literals. Zod at every boundary. Drizzle-inferred row types.
- userId on every user-owned query, in the WHERE clause. Deletes and updates always carry a `where` clause, including on `tx`.
- Never `bun run dev`/`build`, never a browser tool, never `bun run lint`, `bun run check`, `bun run verify` or `format:write` (use `bunx eslint <files>` without `--fix`, and the formatter on owned files only).
- Vitest from the repo root. No git commits.
- RED against typed stubs: add each new module or method first as a typed stub that throws `new Error('not implemented')`, then write the tests, so RED fails at runtime and a project-wide typecheck stays at the baseline (PD-22). Lane 0 packages never sit between RED and GREEN while an audit package or audit check runs (U21).
- Re-read every owned file before editing; cite UI blocks by section id, never line numbers.
- Engine packages: capture characterization pins from the working tree at package start (PD-31); "unchanged" means equal to those pins.
- Every engine request carries the full `EnginePolicy` (PD-26): retained cushion, effective payout request with `FullRequestOnly`, lifetime cap override, path walk, funded day policy, winrate, rr, rebuy lag.
- UI logic that needs a test goes into a `.ts` helper (Vitest includes `tests/unit/**/*.test.ts` only, node environment).
- Wave evidence: typecheck against the recorded baseline, importer greps for every new and deleted module.
