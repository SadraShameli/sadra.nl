# R-V6: live-transfer note texts rechecked against the firms' own live pages (2026-10-02)

Eight notes in `LIVE_TRANSFER_NOTE_TEXT` (`src/lib/prop-calculator/simulator/LiveTransfer.ts`, lines 47 to 66) were checked against each firm's own live website or help center, re-fetched with WebFetch on 2026-10-02. Result: 7 confirmed, 0 contradicted, 1 blocked. The blocked note is Apex (`ApexUserPasteOnly`): every Apex URL tried returned HTTP 403, so the user must paste the Apex Live FAQ. No note text says anything that a live firm page contradicts. Five findings fall short of a contradiction and are listed in "Findings that are not contradictions" below (the Flex note is never shown to a user, the Alpha engine omits a Daily Loss Limit the page lists, the Lucid Daily split on the credit is an inference, FundedNext re-created its help articles under new IDs on 2026-10-01, and two Topstep pages changed this week).

## How the pages were fetched, and limits

- Every fetch was WebFetch on 2026-10-02. The tool turns a page into text and answers my prompt with a small model that caps quotes at about 125 characters and refuses to reproduce a whole article. So I asked for specific sentences. Long sentences appear below as consecutive fragments. I did not diff whole pages, only the sentences each note needs.
- Quotes are exactly as the tool returned them, with its markdown bold markers and link brackets removed. A page or article that is new to this pass is marked "new today". As a check that the tool copies faithfully, I grepped each firm quote against `.claude/prop-firms/` and the two recheck files in this folder. Most already appear there word for word (from the repo's earlier raw-HTML curl passes). The quotes that do not are ones the repo had paraphrased or text that is new today. Each of those is marked "single fetch" (one fetch only), "two fetches agree" (two separate fetches returned the same wording) or "new today".
- No cached copy, Wayback, search engine or third-party site was used. After a 403 I did not retry with a variant URL, another user agent or any other route.
- TPT: the Zendesk HTML help pages return HTTP 403 to WebFetch. `.claude/prop-firms/tpt/SOURCES.md` documents the firm's public Zendesk API (`/api/v2/help_center/en-us/articles.json`) as allowed, so for TPT I used that API's per-article endpoint (`/api/v2/help_center/en-us/articles/<id>.json`) on `takeprofittraderhelp.zendesk.com`.
- Engine statements come from reading `advisor/LivePlanApplicability.ts`, `simulator/LiveTransfer.ts` and the firm classes. I traced the code and did not run the app. One existing test pins the Flex behaviour (`tests/unit/lib/prop-calculator/simulator/LiveTransferHazard.test.ts`, "values the rest at 0 when the firm live model is not verified").
